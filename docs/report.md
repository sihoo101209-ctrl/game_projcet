# 탐구 보고서: MPU6050 기울기 센서를 이용한 게임 컨트롤러 제작

> `[ ]` 칸은 직접 테스트한 결과·사진·느낀 점으로 채울 것

## 1. 탐구 동기
7월 대구한의대 '생성형 AI를 활용한 게임개발자 체험하기' 캠퍼스 탐구에서 게임 개발을 체험했다.
키보드 대신 몸의 움직임으로 조작하는 게임을 만들어 보고 싶어서, 기울기 센서로 직접 컨트롤러를 만들고
유니티 2D 피하기 게임과 연결하는 것을 주제로 정했다.

## 2. 준비물
| 부품 | 용도 |
|---|---|
| 아두이노 나노 | 센서 값을 읽어 PC로 전송 |
| MPU6050 (가속도·자이로 센서) | 기울기 측정 |
| 점퍼선, USB 케이블 | 배선, PC 연결 |
| PC (아두이노 IDE, Unity) | 펌웨어 업로드, 게임 제작 |

## 3. 원리
- MPU6050은 x, y, z 세 축의 가속도를 측정한다. 가만히 있을 때는 중력(1g)만 측정된다.
- ±2g 범위에서 1g = 16384이다. 평평하게 두면 z축 ≈ 16384, x·y축 ≈ 0이다.
- 센서를 θ만큼 기울이면 중력이 옆 축으로 나뉘어 그 축 값이 약 16384 × sinθ가 된다.
  이 값을 16384로 나누면 -1 ~ 1 사이의 기울기 값이 된다.

## 4. 회로
| MPU6050 | 아두이노 나노 |
|---|---|
| VCC | 5V |
| GND | GND |
| SDA | A4 |
| SCL | A5 |

센서와 나노는 I2C 통신(주소 0x68)으로 연결된다.

## 5. 시스템 구조
```
MPU6050 ─I2C→ 아두이노 나노 ─USB 시리얼(115200bps, "ax,ay,az")→ Unity
                                                     SerialReceiver: 문자열 → 기울기(-1~1)
                                                     PlayerMove: 기울기 → 좌우 이동
```
- 아두이노: 약 50Hz(20ms마다)로 세 축 가속도를 한 줄 문자열로 전송
- Unity: 별도 스레드에서 시리얼을 읽어 게임 화면이 끊기지 않게 함

## 6. 게임 구성
- 장르: 위에서 떨어지는 장애물을 피하는 2D 게임
- 조작: 센서를 좌우로 기울이면 플레이어가 그 방향으로 이동 (많이 기울일수록 빠름)
- 장애물에 닿으면 게임 오버, Restart 버튼으로 재시작
- 점수: 생존 시간(초)

| 스크립트 | 역할 |
|---|---|
| mpu_read.ino | 센서 값 읽고 시리얼로 전송 |
| SerialReceiver.cs | 시리얼 수신, 기울기 계산, 시작 자세 보정 |
| PlayerMove.cs | 플레이어 이동, 데드존(떨림 무시) |
| Obstacle.cs | 장애물 낙하, 충돌 시 게임 오버 |
| Spawner.cs | 일정 간격으로 장애물 생성 |
| GameManager.cs | 점수, 게임 오버, 재시작 |

## 7. 제작 과정에서 고려한 점
| 문제 | 해결 |
|---|---|
| Unity 기본 설정에서는 시리얼 통신(System.IO.Ports)을 쓸 수 없음 | Api Compatibility Level을 .NET Framework로 변경 |
| 게임 루프에서 시리얼을 기다리면 화면이 끊김 | 시리얼 읽기를 별도 스레드로 분리 |
| 9600bps는 50Hz 전송량을 감당하기 빠듯해 반응이 밀림 | 115200bps로 속도 향상 |
| 재시작하면 포트가 이미 열려 있어 다시 열리지 않고, 다시 열면 나노가 리셋됨 | 시리얼 오브젝트를 씬이 바뀌어도 유지(DontDestroyOnLoad) |
| 손 떨림 때문에 가만히 있어도 플레이어가 움직임 | 데드존(0.1) 설정 |
| 센서를 쥐는 각도가 사람마다 다름 | 시작 후 20개 값의 평균을 기준(0)으로 보정 |
